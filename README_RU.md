# 737 NG Offline Trainer — демонстрационный PWA

Это самостоятельный учебный прототип. Он **не содержит** корпоративных FCOM/FCTM/QRH, реальных Memory Items или эксплуатационных Limitations.

## Запуск на iPhone/iPad
1. Распакуйте архив и опубликуйте **только эту демонстрационную оболочку** как статический HTTPS-сайт, например через GitHub Pages. Не публикуйте корпоративные вопросы, QRH/FCOM/FCTM и закрытые материалы.
2. Откройте полученный адрес в Safari iPhone/iPad при наличии интернета.
3. Через «Поделиться» выберите «На экран Домой» → «Добавить», при наличии переключателя оставьте «Открывать как веб-приложение».
4. Откройте иконку 737 Trainer. Запустите один тест. После первого открытия приложение использует кэш Service Worker.
5. Включите авиарежим и **полностью закройте приложение, затем снова откройте**. Проверьте, что все разделы работают.
6. Внутри установленного приложения перейдите в «База / резерв» и импортируйте свою JSON-базу. Импортируемый файл обрабатывается только на устройстве: приложение не использует внешние API. По умолчанию новые вопросы добавляются, а существующие остаются без изменений.

### Пример деплоя GitHub Pages
Создайте **публичный репозиторий только с кодом прототипа и демонстрационной базой**. Загрузите в корень репозитория файлы `index.html`, `app.js`, `sw.js`, `manifest.webmanifest`, `icon-192.png`, `icon-512.png`. В `Settings` → `Pages` укажите `Deploy from a branch`, ветку `main`, папку `/ (root)`. Подождите, пока GitHub опубликует URL `https://USER.github.io/REPO/`. Адрес сайта требуется для **первого запуска и возможных обновлений программы**, но не для тестов после кэширования. URL изменяется по настройкам репозитория.

**Важно:** публичная оболочка ≠ публичный корпоративный банк. Никогда не вставляйте закрытые документы или ответы в `app.js` и в репозиторий. Банк импортируется на самом iPhone/iPad из приватного JSON.

## JSON-формат
Скачайте «Шаблон банка» в приложении. JSON должен выглядеть так:

```json
{
  "schemaVersion": 1,
  "title": "Мой учебный банк",
  "operator": "Название оператора или внутренний идентификатор",
  "aircraft": "B737 NG",
  "bankRevision": "2026-11-23",
  "items": [
    {
      "id": "example-001",
      "type": "quiz",
      "topic": "Electrical",
      "prompt": "Здесь текст вопроса, сверенного с руководством",
      "options": ["Вариант A", "Вариант B", "Вариант C", "Вариант D"],
      "correctIndices": [0],
      "answer": "Вариант A",
      "explanation": "Объяснение на основе проверенного пункта руководства",
      "source": {
        "document": "FCOM",
        "section": "Полное название раздела",
        "page": "Номер страницы или пункта",
        "revision": "Номер / дата действующей редакции",
        "verified": false
      }
    }
  ]
}
```

Значения `type`: `quiz`, `memory`, `limitation`, `interview`. Для остальных типов (`memory`, `limitation`, `interview`) поля `options` и `correctIndices` не нужны, а в `answer` укажите точный проверенный текст/значение и условия применения. Для вопросов с несколькими правильными ответами в `correctIndices` используйте, например, `[0, 2]`. Нумерация вариантов начинается с нуля. Приложение не проверяет соответствие корпоративному руководству автоматически: поле `verified=true` — только пометка автора базы.

## Прототип и ограничения
- Накопительный импорт JSON (добавление, обновление совпадающих ID, полная замена), тесты, карточки, статистика и резервное копирование работают локально. При обновлении вопроса с изменённым содержимым его история ошибок и интервального повторения сбрасывается, но общие исторические счётчики сохраняются.
- Отметка «Знаю» планирует карточку на 1, 3, 7 или 14 дней, но в текущей версии **не скрывает** ещё не наступившие карточки из набора: она лишь меняет их порядок.
- Данные хранятся в `localStorage` установленного приложения. Это не надёжное постоянное хранилище для больших баз и изображений. До добавления сотен изображений рекомендуется перейти на IndexedDB.
- Резервную копию можно экспортировать в JSON и восстановить через импорт. Храните бэкапы в месте, разрешённом правилами оператора.
- Web App может потерять локальные данные при очистке хранилища/удалении приложения/нехватке места. Регулярно экспортируйте прогресс.
- После обновления кода `sw.js` надо увеличить значение `CACHE`, чтобы гарантировать загрузку обновлённого интерфейса.
- В настоящем приложении желательно дополнительно: полноценное редакторское ревью, привязка к конкретному борту/конфигурации, управление версиями источников, журнал изменений, IndexedDB, поддержка вложенных иллюстраций, верификация импорта.

## Безопасность и точность
Не использовать приложение вместо актуальных эксплуатационных документов, SOP и обучения оператора. Фактические Memory Items/Limitations вводить только после ручной сверки по разрешённым корпоративным материалам с сохранением редакции, условий применения и ссылки на первоисточник.

## Накопительный импорт (версия 2)
- Выберите режим **«Добавить только новые вопросы»**: одинаковые ID не дублируются и не перезаписываются.
- **«Добавить и обновить совпадающие ID»**: существующие вопросы с изменённым содержимым заменяются. История повторения только этих вопросов сбрасывается.
- **«Полностью заменить банк / восстановить копию»**: используется для целостного восстановления, при загрузке backup можно отдельно подтвердить восстановление статистики.
- Стабильные ID обязательны: `fcom-elec-001`, `fcom-elec-002`. При исправлении вопроса сохраняйте тот же ID; для нового вопроса создавайте новый.
- Публичный репозиторий содержит только демонстрационную оболочку. Вопросы, импортированные через iPhone, остаются локальными; предоставление JSON друзьям — отдельное решение с учётом прав на материалы.
- Важно: данные по-прежнему в `localStorage`, что ограничивает размер банка. Перед крупным импортом и обновлениями сохраняйте backup. Для больших коллекций и иллюстраций нужен IndexedDB.
